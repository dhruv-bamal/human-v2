# Together / Thirty — implementation plan

Next.js App Router + TypeScript + Tailwind on Vercel. Supabase Auth owns identity; PostgreSQL owns private plan definitions and progress. Use the Supabase data API with the signed-in user's JWT for application queries so RLS is never bypassed. Use postgres.js only for explicit developer migration/seed/link/verification scripts, with prepared statements disabled for pooler compatibility.

Relational definitions: programs, program_days, plan_tasks, meal_slots, meal_options, program_notes, metric_definitions. Separate mutable profiles (exactly two permitted slugs, linked to auth.users), task_progress, meal_progress, measurements, weekly_checkins. Compound foreign keys prevent mixing another profile's tasks or invalid day references. A trigger enforces actual-date meal slots and disallows future writes even through direct data API access. RLS permits the two mapped accounts to read both profiles and only write their own progress. No browser receives an admin credential. No signup or public data route.

Routes: /login, /app/today, /app/[person]/[overview|exercise|meals|progress]. Day is a validated query parameter, allowing history and upcoming plan inspection. Server rendering loads authenticated data; small client task/meal/check-in forms handle mutations and explicit errors. All updates are idempotent upserts with server-derived identity. Refresh provides authoritative values; pending controls prevent duplicate clicks.

Dates: PostgreSQL app_settings and server APP_TIMEZONE must agree (Asia/Kolkata by default). Store date-only start dates and UTC timestamps. Annanya workout and meal sequence stays attached to program day. Dhruv workouts follow program day; every meal follows actual calendar weekday. Unset starts allow plan inspection but no tracking. Start date can be set once by owner before tracking; later correction is an explicit developer operation, never a casual reset.

Visual direction: an ink-blue private training journal, warm white surfaces, clear serif headings, precise compact data, blue Dhruv / plum Annanya accents, and a 30-day calendar as the shared visual anchor. No fictional activity, stock athlete imagery, or public preview containing private programs.

Validation: full source extraction audit, 60-day mappings, date boundaries and weekday menus, completion/rest/optional meals, server authorization helper tests, real PostgreSQL RLS tests in embedded PGlite, lint/typecheck/production build, browser review at desktop/mobile. Live Supabase/Auth/Vercel checks remain dependent on supplied configuration.
