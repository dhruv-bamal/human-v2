# Together / Thirty — architecture

Next.js App Router + TypeScript + Tailwind on Vercel. Supabase Auth owns identity; PostgreSQL owns private plan definitions and progress. Application queries use the signed-in user's session and never bypass RLS. postgres.js is restricted to explicit migration/seed/link/verification scripts, with prepared statements disabled for pooler compatibility. Administrative credentials are not deployed in the web app.

Definitions: programs, program_days, plan_tasks, meal_slots, meal_options, program_notes, metric_definitions, recipes, recipe_ingredients, recipe_steps and meal_recipe_links. Profiles are exactly two permitted slugs linked to auth.users. Separate task_progress, meal_progress, measurements and weekly_checkins record activity. Compound foreign keys prevent mixing another profile's tasks or invalid day references. The progress trigger checks the appropriate meal rotation and due date. All 17 application tables (including app_settings) have RLS; definition tables have member SELECT only, progress tables have owner INSERT/UPDATE only. No client DELETE access.

Routes: /login, /app/today, /app/[person]/[overview|exercise|meals|progress]. Day is a validated query parameter for history/future inspection. Server rendering loads authenticated data; small client controls call independently authenticated server actions with schema validation. Completion and notes use idempotent upserts and explicit pending/error feedback. Meal Prep uses a native modal dialog with ephemeral ingredient checks. It never introduces a separate recipe completion target.

The daily loader retains lightweight task/meal metadata for both profiles' totals, detailed exercises only for the selected day, and one nested recipe query restricted to selected-day meal IDs. Ingredients and steps are independently relational and explicitly ordered; links support multiple recipes per meal. Annanya has no recipe links and her original behavior remains unchanged. All ten recipe definitions live in the deterministic seed, not React components. Six source-derived kitchen notes provide the Meal Prep Guide.

Dates: PostgreSQL app_settings and APP_TIMEZONE must agree. Start dates are date-only; audit timestamps are UTC. The evening date anchors Dhruv's three events. Real weekday derives from start + program day - 1; snack and post-workout display with calendar offset +1 but save to the same program day. Dhruv's current training date changes at 5 AM; Annanya's at midnight. Routes, partner summaries, actions and SQL guards use the same rule. The 5 AM cutoff is a documented application convention based on the updated PDF's sleep/wind-down routine.

Migration 002 is additive. Existing pre/post meal IDs remain stable and a new snack ID is inserted; no tracking or profile rows are rewritten. Seed upserts share an advisory lock with migrations and never mutate recorded progress or start dates. A regression test applies the migration to old-schema personal records and checks every field survives; another compares all Annanya definitions against the baseline.

Visual design: ink-blue journal, white surfaces, serif headings, blue Dhruv / plum Annanya accents. The phone prep sheet provides large ingredient labels, numbered steps and a sticky explicit completion action. Both partners can read recipes; peer checks and saves are disabled. Authorization is independently enforced by server actions and PostgreSQL.
